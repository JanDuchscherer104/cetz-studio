# Scientific figures

Make the scientific relationship visible. Own visual explanation and comparison;
the consumer project's source, data and scientific review own what is true.

## Enter at the requested phase

| Request | Action |
| --- | --- |
| New figure, redesign, unresolved renderer | Follow the design loop below. |
| Accepted composition or compile-only repair | Go directly to the project's format/build owner; preserve the lesson. |
| Mermaid syntax or local renderer failure | Before editing, run the supplied local wrapper and capture its parser error; then follow the [renderer repair recipe](references/renderers.md). |
| Gallery lookup or supplied preference | Use the project's catalog owner; a preference does not approve or include a figure. |
| Scientific validity or changed argument | Use the project's independent review or manuscript owner before treating the claim as settled. |
| Canvas/voice collaboration | Keep conversation and voice in the external agent client. Use the project's actual viewer/editor separately and hand source changes across explicitly; this skill does not create connectivity. |

Use the project's `AGENTS.md` and supplied figure profile. When the project has
no explicit profile, [project context](references/project.md) describes the few
facts to locate and what may remain unknown. Installation does not supply or
invent those facts. Reach only the references needed by the current branch.

## Design loop

1. **Lesson.** Inspect the current figure, its destination and closest useful
   alternative. State one reader question, the relationship the figure adds,
   destination width and retained content. Finish with a distinct lesson or
   retain the existing figure; more panels need distinct questions.
2. **Evidence.** Open the exact definition, implementation or input behind each
   depicted relationship. Use [evidence and geometry](references/evidence.md)
   for scientific/3D inputs. Finish with a source-to-visual mapping, declared
   construction/evidential role and explicit unknowns. Visual plausibility does
   not resolve a disagreement in the scientific owners.
3. **Construction.** Choose the representation using the single
   [renderer-selection reference](references/renderers.md). Reuse actual shared
   primitives and notation; declare what color, stroke, size, arrows and
   visibility encode. Finish with a bounded composition and a named rendering
   route. A package import does not grant reversible editing.
4. **Comparison.** Render through that route and inspect at the destination
   size. For redesign or style comparison use [iteration](references/iteration.md).
   Keep the same scientific inputs across alternatives. Finish with an inspected
   candidate, one concrete revision, or a named missing-render/inspection gap.
5. **Decision.** Correct scientific errors before polish. Preserve the accepted
   baseline if the candidate is rejected. Obtain independent scientific review
   through the project owner when required; identify a self-review as such.
   Finish with a selected candidate or unresolved decision, not an implied approval.
6. **Integration.** Only when authorized, hand the selected figure to the
   project's manuscript/format owner for its caption, prose, inclusion and
   destination-page inspection. Otherwise deliver the candidate and its proof.

## Return

Name the lesson, source/input/render identities, exact checks and visual
inspections, limitations, and the selection/inclusion state. Distinguish
compilation, scientific validity, visual acceptance, preference and actual
publication. No additional registry or automatic scientific approval is created.

For changes to this skill, exercise the [routing scenarios](evals/README.md).
Static link/frontmatter tests are not evidence of actual agent routing quality.
